## Stack elegido (y por qué)

| Parte | Elección | Por qué |
|---|---|---|
| Frontend | Vite + React 19 + TypeScript | Ya sabés React; TS te ahorra bugs en el catálogo y el carrito y suma al CV |
| Estilos | Tailwind v4 con tokens propios | Rápido para iterar la estética de diario sin pelear con CSS |
| Rutas | React Router 7 | Estándar, simple para un sitio de pocas páginas |
| Catálogo | Archivo `products.ts` en el repo | Con pocos productos no hace falta base de datos; editás y deployás |
| Pedidos | `POST /api/pedido` en Cloudflare Pages Functions + aviso por Telegram, y después WhatsApp con N° de boleta | El servidor verifica el pedido contra el catálogo y calcula el total (nunca confía en precios del cliente); sin comisiones, el pago se sigue coordinando por chat |

| Datos compartidos (después) | Cloudflare Pages Functions + D1 | Todo queda en Cloudflare, sin servidor aparte (decisión del 2026-10-19). La base D1 se suma recién cuando una función tenga que guardar datos compartidos (Carnet de lector como cuenta, Premios Plainview, Mercado Pago) |

## Concepto: La Edición

El sitio es un **diario viejo mezclado con un catálogo de venta por correo del lejano oeste**: vas pasando
las páginas. Cada drop sale como una **edición** con número y fecha, y cada remera es un **artículo**
del catálogo, con número, precio, descripción y detalles. El "Watch closer" es la forma de leer: mirar
cada página de cerca.

| Pieza de tienda | En La Edición | Ejemplo |
|---|---|---|
| Portada | Primera plana | Cabecera, fecha de hoy, "Edición N° 1" |
| Drop / colección | Edición | "Edición N° 1 · Córdoba · 16 oct 2026" |
| Catálogo | Índice de avisos + un aviso por página que se pasa deslizando | "Art. N° 001 — Magnolia" |
| Remera | Aviso comercial estilo catálogo por correo | Titular grande, precio en recuadro, grabado, texto de aviso, tabla de medidas, cupón "Recorte y agregue a su pedido" |
| Referencia | Recuadro "Fe de erratas: mirá de nuevo" | Se despliega al tocarlo |
| Estado | En existencia / Por encargo / Próximo número | disponible / preventa / próximamente |
| Juego | Pasatiempos | El Cifrado, Cinedoku, Crucigrama del Valle; después Mirá de Cerca y La Función del Día (ver `docs/PASATIEMPOS.md`) |
| Cómo comprar | Página propia (sin clasificados) | Pasos, guía de talles, pagos, envíos y cambios |
| Avisos | Avisos chicos sueltos (`anuncios.ts`): "mini" con ilustración y "línea" | Entre las noticias de la portada, al pie de cada aviso comercial y en Pasatiempos; nunca en una página propia |
| Carrito | Boleta de pedido | Cupón recortable que se verifica en el servidor y sale por WhatsApp con su N° de boleta |
| Footer | Pie de página + pie de imprenta | "← pág. anterior · Índice · pág. siguiente →", fecha, staff, @plainview.82 |
| 404 | Fe de erratas | "Esta escena se cortó en el montaje" |

Estética: papel crema sobre fondo oscuro, tipografías de época, rojo (`--color-red`) solo para el 8:2 y acentos.

Reglas del concepto:
- Mobile-first (ver CLAUDE.md): las páginas del catálogo se pasan con el dedo, pero también con botones
  anterior/siguiente y con las flechas del teclado; nada depende solo del gesto.
- Cada página del catálogo tiene **URL propia** (se puede compartir un artículo por WhatsApp o Instagram).
  Las rutas viejas (`/producto/:slug`) redirigen a la nueva, para no romper links ya compartidos.
- Comprar nunca queda escondido detrás de la metáfora: precio, talle y botón siempre a la vista.
- Todo con CSS y los tokens de `index.css` (filetes, capitulares, View Transitions); sin librerías nuevas.

### Todo el sitio es el diario: `NewspaperPage`
- **Layout común** para todas las rutas (reemplaza a `Layout.tsx`). La portada conserva la cabecera grande
  (`Masthead`) y es la pág. 1; el resto lleva una **cabecera chica**: logo giratorio (sin recuadro),
  "THE PLAINVIEW", número de página y nombre de la sección.
- **Pie de página:** "← pág. anterior · Índice · pág. siguiente →", la fecha y el pie de imprenta.
- **Orden de páginas** en `src/data/paginas.ts`, armado a partir de productos y secciones: Primera plana →
  Índice de avisos → un aviso por producto (por `articulo`) → Pasatiempos → Cómo comprar → Boleta.
  El número de página es la posición en esa lista; el 404 (Fe de erratas) queda afuera.
- **Pasar de página:** deslizando en el celular (pointer events nativos, umbral ~60px y solo si el gesto es más
  horizontal que vertical), con ← → en la compu (salvo con el foco en un campo o un tablero) y siempre con los
  botones del pie.
- **Transición de hoja:** View Transitions API (la prop `viewTransition` de React Router 7 + CSS
  `::view-transition-*`), un deslizamiento sutil con sombra según la dirección. Con reduced motion o sin soporte
  del navegador, cambia sin animación. Con una URL por página, navegar entre rutas es más simple que un
  carrusel con `scroll-snap`.

## Etapa 2 — Pedidos verificados en el servidor (4 sesiones)
Decisión del 2026-10-17: los pedidos se verifican en el servidor antes de llegar a WhatsApp. Se integra con la boleta
(S6/S7) para no construirla dos veces: primero el endpoint, después la boleta que lo usa.

**Flujo:** boleta → `POST /api/pedido` → la función valida contra el catálogo, calcula el total, genera el N° de
boleta y avisa por **Telegram** → responde `{ boleta, resumen, total }` → recién ahí se abre **WhatsApp** con el N°
de boleta y el resumen que armó el servidor.

**Reglas del endpoint** (`web/functions/api/pedido.ts`, Cloudflare Pages Functions):
- **Recibe solo** `slug`, `talle`, `color` y `cantidad` por ítem (más los datos del pedido y el token de Turnstile en S7).
  **Nunca precios**: el total se calcula en el servidor con el mismo `products.ts` que usa el sitio.
- **Validación estricta:** `Content-Type: application/json`, cuerpo chico (por ejemplo, 4 KB), solo claves conocidas
  (si sobra alguna, 400), slug existente y "disponible", talle y color dentro de los de ese producto, cantidad entera
  de 1 a 10, máximo de ítems, textos con largo máximo y sin caracteres de control. Errores 400 genéricos
  (sin contar qué falló).
- **N° de boleta** generado en el servidor (por ejemplo `PV-AAMMDD-XXXX` con `crypto.getRandomValues`).
- **Credenciales** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TURNSTILE_SECRET_KEY`) como variables/secretos de
  Cloudflare, **sin `VITE_`**: nunca llegan al navegador (ver "Seguridad" en CLAUDE.md).
- **Turnstile:** widget en la boleta y verificación del token en la función (`siteverify`). La CSP de `_headers`
  suma `https://challenges.cloudflare.com` en `script-src` y `frame-src`.
- **WhatsApp después del `await`:** se navega en la misma pestaña. Un `window.open` después de esperar la respuesta
  lo bloquea el navegador como pop-up.
- **Desarrollo local:** `wrangler pages dev` para correr las Functions (wrangler es una dependencia nueva: preguntar
  antes de sumarla).
